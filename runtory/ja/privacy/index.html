第1条（管理者と処理目的）

Meongstore（멍스토어）は、RUNTORYのアカウント認証、ランニング記録、ゲーム進行、フレンド、バックアップ・復元、サブスクリプション、無料利用者向け広告、サポートおよび法的義務のために必要な情報を処理します。現在のリモートアカウント権限はFirebase Authenticationです。iOSとAndroidの両方でSign in with AppleとGoogleログインをFirebase認証手段としてサポートします。リモートプロフィール・フレンド・構造化バックアップはCloud Firestore、大容量の経路・記録写真バックアップ資産はCloud Storage for Firebase、機密性の高いサーバー処理はCloud Functions for Firebaseを使用します。

第2条（処理する情報）

  • FirebaseユーザーID、Apple/Googleログイン識別情報、提供される場合のメール・表示名
  • 必須同意の版・日時・言語、14歳以上確認
  • プロフィール表示名、フレンドコード、フレンドリクエスト・関係、週間ランニング集計
  • 正確な位置、完了ランのGPS座標・順序・時刻、距離・時間・ペース・カロリー、モーション・歩数
  • 利用者が選択した記録写真とアプリ管理コピー
  • ペット、卵、チャレンジ、チケット、インベントリ、バッジ、クエスト、設定、バックアップ
  • ストア商品・取引・検証状態、アカウント紐付け、Plus権限
  • Firebase App Check等のセキュリティ・整合性要求情報
  • 広告同意状態および広告配信に必要なアプリ・端末・SDK情報。Google Mobile AdsはIPアドレスに基づく概略位置、広告表示・操作、診断・性能情報、設定に応じた端末識別子等を処理する場合があります。

カード番号や銀行口座番号をRUNTORYが直接収集・保存することはありません。

第3条（保存・保有・削除）

データは端末内のDrift/SQLite、SharedPreferences、アプリ管理ファイルに保存される場合があります。完了ランのローカル生GPS経路は365日を超えた後の次回通常起動時に削除されます。経路を再構成しない要約は残る場合があります。

ログイン済み利用者のリモートバックアップはCloud Firestoreの構造化データとCloud Storage for Firebaseの正確な完了ラン経路・アプリ管理の元写真資産を含む場合があります。これらのリモートバックアップはローカル365日経路削除とは別のライフサイクルを持ちます。個別記録・写真削除、バックアップ更新、アカウント削除時の整合性は実際のサービス動作に従います。

アカウント、フレンド、ゲーム・設定情報はサービス提供に必要な期間保有し、利用者が削除するかアカウントを削除した場合、法令上別途保存義務がある場合を除き削除します。位置利用事実確認資料は関連法令に基づく確認・権利行使対応のため保管し、位置同意の撤回またはアカウント削除時には現在の利用者に対する削除手続を行います。

第4条（Firebase、Appleサービス、旧CloudKit）

Firebase Authenticationは現在のリモートアカウント権限です。Cloud Firestoreはプロフィール・フレンド・構造化バックアップ等を、Cloud Storage for Firebaseは正確なランニング経路やアプリ管理の元写真等の大容量バックアップ資産を処理する場合があります。Cloud Functions for Firebaseはバックアップ確定・保有整理、アカウント削除、サブスクリプション検証、位置利用事実の記録・削除等の機密サーバー処理を行い、Firebase App Checkはサーバー要求の整合性保護に使用されます。

Sign in with AppleとGoogleログインは対応するiOS・AndroidでFirebaseアカウントの認証手段として使用します。App Store/StoreKitはiOSの購入・更新・復元・取引検証を提供します。RUNTORYアカウントまたはアプリの削除はApp Storeサブスクリプションを自動解約しません。

CloudKitは現在のアカウント・フレンド・バックアップ保存先ではありません。ただしFirebase移行前に作成された位置利用事実確認資料について、撤回・アカウント削除の権利を処理するため、iOSに最小限の旧削除経路が一時的に残っています。この経路は過去のApple連携identityを確認して過去資料を読み取り・削除する用途に限られ、新しいアカウント・フレンド・バックアップ・位置利用事実資料をCloudKitへ作成しません。

第5条（広告とGoogleサービス）

無料利用者にはGoogle Mobile Adsのバナーおよびリワード広告が表示される場合があり、Google UMPが広告リクエストの可否とプライバシー選択を管理します。現在の構成ではNPA・RDPシグナルを適用し、publisher first-party IDを無効化し、ATT権限を要求しません。Plus利用者にはアプリ側で広告リクエストを停止します。

NPA/RDPはGoogleのLimited Adsと同一のモードではなく、識別子処理が一切ないことを意味しません。広告頻度、集計、セキュリティ、不正トラフィック防止、診断等に必要な処理が発生する場合があります。

第6条（国外処理と外部サービス）

RUNTORYはFirebase/Google Cloudバックエンド、Appleログイン・App Storeサブスクリプション、Google広告サービスを利用します。同じGoogle系サービスでも役割とデータ経路が異なるため、Firebaseバックエンドの処理委託・保管とGoogle広告SDKの直接収集を区別して説明します。韓国個人情報保護法第28条の8に基づく国外処理の開示は、実際のリリース構成と事業者契約・処理地域を基準に適用します。

Firebase / Google Cloudバックエンド

  • 処理委託・保管の根拠: 利用者とのサービス契約の締結・履行に必要なアカウント、同期・バックアップ、セキュリティ、アカウント削除、サブスクリプション検証、法的義務処理のうち国外処理に該当する範囲について、韓国個人情報保護法第28条の8第1項第3号を適用します。
  • 契約事業者・処理者: Googleの現在のGoogle Cloud契約法人案内では、韓国の請求先顧客について別途合意がない限りGoogle Cloud Korea LLCが記載されています。実際のサービス提供にはGoogle関連会社および公表されたサブプロセッサが関与する場合があります。関連基準はGoogleプライバシーポリシーと適用されるFirebase/Google Cloud契約に従います。
  • 処理情報: FirebaseユーザーID、認証・整合性要求情報、プロフィール・フレンド・バックアップ構造化データ、バックアップ経路・記録写真資産、位置利用事実確認資料、アカウント削除・サブスクリプション検証に必要な参照・サーバー作業情報。
  • 現在の保存・処理地域: 2026年8月28日に確認したproduction設定では、Cloud Firestore既定データベースとFirebase Storageバケットは韓国ソウルリージョン（asia-northeast3/ASIA-NORTHEAST3）、現在の機密Cloud Functionsは米国us-central1で処理されます。Firebase Authentication、App Check、技術支援・運用およびサブプロセッサ処理は、選択したデータベース・バケットリージョンとは別にGoogleまたはサブプロセッサが施設を運営する国で発生する場合があります。
  • 時期・方法: ログイン、プロフィール・フレンド、バックアップ・復元、アカウント削除、サブスクリプション検証、位置利用事実の記録・削除等の機能利用時に暗号化されたネットワーク通信で処理されます。
  • 目的: 認証・セキュリティ、リモートプロフィール・フレンド、バックアップ・復元、サーバー検証、アカウント削除、法的義務およびサービス運用。
  • 保有期間: RUNTORYが管理するデータは本ポリシーと各機能の削除・保有方針に従います。Googleのサービス運用・セキュリティ・サブプロセッサ処理には適用契約・ポリシーが適用されます。
  • 拒否方法・影響: 基本的なランニング・端末内の記録・ペットなどのローカル機能は、RUNTORYアカウントなしで利用できます。Firebaseのリモートアカウント処理を希望しない場合は、フレンド・クラウドバックアップなどのアカウント機能を利用しないことを選択できます。アカウント機能の利用時にはログインが必要です。アカウントデータ削除はアプリのアカウント削除機能から要求できます。

Appleサービス

  • 処理経路: Sign in with Apple認証とApp Store/StoreKitの購入・復元・取引検証に必要な範囲でAppleサービスを利用します。現在のRUNTORYアカウント・フレンド・バックアップ保存先はCloudKitではありません。
  • 事業者・連絡先: Appleが案内する韓国利用者向け関連法人、Apple Inc.および関連処理者が関与する場合があります。問い合わせはApple Privacy Contactを利用できます。
  • 処理される可能性のある情報: Appleログイン識別情報、Appleから提供される場合のメール・表示名、App Store/StoreKit商品・取引・検証・アカウント紐付け情報。
  • 目的・別管理: Appleログインによるアカウント認証、App Store決済・サブスクリプション、StoreKit取引検証、セキュリティ・運用。Appleが独立して保有するアカウント・決済・取引・セキュリティ情報はAppleのポリシーと法的義務に従い、RUNTORYアカウント削除だけではApp Storeサブスクリプションは自動解約されません。

Google広告サービス

  • 事業者・連絡先: Googleは韓国のAdMobパブリッシャーの契約法人としてGoogle Asia Pacific Pte. Ltd.を案内しています。処理基準と問い合わせ経路はGoogleプライバシーポリシーで確認できます。
  • 直接収集経路: Google Mobile Ads SDK/UMPが広告提供時に利用者端末からGoogleへ関連情報を直接収集・処理する場合があります。RUNTORYは広告リクエストにアカウントID、メール、正確なGPS経路、記録写真を独自広告パラメータとして渡しません。
  • 処理される可能性のある情報: 広告・プライバシー選択状態、アプリ・端末・SDK情報、IPアドレスによる概略位置、設定に応じた端末識別子、広告表示・操作、診断・性能・セキュリティ・不正トラフィック防止情報。
  • 処理国の範囲: Googleは世界中にサーバーを運用し、居住国外で処理される場合があると公表しています。広告経路の固定データセンター国を契約法人の所在地だけから推測しません。
  • 現在の構成: UMPの広告要求可否に従い、NPA・RDPを適用し、publisher first-party IDを無効化し、ATTを要求しません。NPA/RDPはGoogleのLimited Adsと同一ではなく、識別子処理が全くないことを意味しません。Plus利用者には広告要求を停止します。

Firebaseリージョン、事業者、広告/SDK構成または処理範囲が実質的に変わる場合、実際のリリース候補と事業者公開資料を基準に本条を再確認し、必要な通知・同意手続きを適用します。

第7条（利用者の権利）

利用者はアプリで利用可能な記録・写真の削除、位置同意の撤回、ログアウト、アカウント削除を行えます。法令上の閲覧、訂正、削除、処理停止等の請求はサポートにも提出できます。

iOSでは旧CloudKit位置利用事実の削除経路を先に試み、その後Firebaseサーバーが認証済み削除要求を耐久的に受理してからアカウント削除手続が進みます。受理後、アプリは当該ユーザー範囲のローカルデータを整理し、サーバーの耐久的削除ジョブがリモートのバックアップ・フレンド・プロフィール・アカウントデータを継続して物理削除・再試行します。

第8条（権限と保護措置）

位置情報は利用者が開始した屋外ランの距離・経路記録、モーション・フィットネスは屋内ラン・歩数、写真ライブラリは選択した記録写真、Sign in with AppleとGoogleログインはiOS・Androidのアカウント認証に使用します。利用者範囲分離、owner検証、アクセス制御、通信保護、正確な経路をリリースログに出さない措置等を適用します。

第9条（14歳未満）

RUNTORYは14歳以上を対象とし、14歳未満向けの法定代理人同意フローを提供しません。生年月日や法定代理人情報を別途収集しません。
