앱에서 삭제 요청

로그인한 이용자는 런토리 설정 → 계정 삭제에서 요청할 수 있습니다. iOS에서는 Firebase 계정이 살아 있는 동안 확인할 수 있는 전환 전 과거 CloudKit 위치 이용사실 자료의 삭제 경로를 먼저 시도합니다. 그 다음 Firebase 서버가 인증된 계정 삭제 요청을 안전하게 접수해야 앱이 접수된 삭제 절차를 계속합니다.

삭제되는 런토리 데이터

  • Firebase Authentication의 런토리 계정
  • Cloud Firestore의 프로필·친구·구조화 계정 백업 등 계정 범위 데이터
  • Cloud Storage for Firebase의 계정 백업 러닝 경로·앱 관리 기록사진 자산
  • 서버 정책상 삭제 대상인 계정 범위 운영 데이터와 위치 이용사실 확인자료
  • 이 기기의 해당 사용자 범위 Drift 데이터, 러닝 경로, 앱 관리 사진과 게임 진행 데이터
  • iOS에서 접근 가능한 전환 전 CloudKit 위치 이용사실 확인자료의 레거시 삭제 절차

삭제 처리 순서와 재시도

Firebase 서버가 삭제 요청을 영속적으로 접수한 뒤 앱은 해당 사용자 범위의 로컬 데이터를 정리합니다. 서버는 접수된 삭제 작업을 기준으로 원격 접근을 차단하고 Firebase 백업·친구·프로필·계정 데이터의 물리적 삭제를 계속 수행합니다. 네트워크 또는 서버 오류로 물리 삭제가 즉시 끝나지 않으면 서버 작업은 재시도 가능한 상태를 유지하며, 서버가 요청을 접수하지 못한 상태를 삭제 성공으로 표시하지 않습니다.

별도로 관리되는 항목

  • App Store/Google Play 구독: 런토리 계정 삭제로 자동 해지되지 않으며 각 스토어의 구독 설정에서 별도로 관리해야 합니다.
  • 스토어가 보유하는 결제·거래 기록: 각 스토어의 정책과 법적 의무에 따라 별도 관리될 수 있습니다.
  • 기기 사진 보관함: 사용자가 사진 앱에 보관한 원본은 런토리 계정 삭제 대상이 아닙니다.
  • 운영체제 위치 권한: 기기 설정에서 별도로 변경할 수 있습니다.

Sign in with Apple / Google 접근 권한

런토리 계정을 삭제해도 Apple 또는 Google 계정 설정의 앱 연결 상태는 별도로 남을 수 있습니다. 필요한 경우 해당 계정의 연결된 앱/로그인 설정에서 RUNTORY 접근 권한을 별도로 관리할 수 있습니다.
